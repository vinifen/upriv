# Commits

## Author identity (mandatory)

The **only** author (and committer) of a Git commit in this repository is the **human** identity Git is already configured to use.

Agents and editors are writing assistants. They are **never** the Git author, committer, or co-author.

### Do

- Call `git commit` **without** `--author`.
- Use Git’s **effective** identity: **local** `user.name` / `user.email` if set, otherwise **global**. Check with `git config user.name` and `git config user.email` (no flags). If either is empty, **stop** and ask the human. Do not invent a name or email.
- After every commit, **verify** (see [How agents commit](#how-agents-commit)).

### Do not

- Run `git config` (including to set `user.name` / `user.email`) unless the human explicitly asked to change Git configuration.
- Pass `--author`, `--trailer`, or any flag that changes identity.
- Add any of these for an AI, model, or tool (Cursor, Copilot, Claude, ChatGPT, Grok, Composer, or similar):
  - `Co-authored-by:`
  - `Signed-off-by:` (when it credits a tool)
  - `Made-with:`, `Generated-by:`, `Generated with`, `Assisted-by:`
  - Subject/body lines that name the model (“generated by …”, “with Cursor”, …)
- Use a placeholder author such as `Cursor`, `AI`, `Agent`, or a product email (`cursoragent@cursor.com`, …).

**Wrong**

```text
feat(desktop): add vault info modal

Co-authored-by: Cursor <cursoragent@cursor.com>
```

**Right** — message only; author and committer are the **effective** `user.name` / `user.email` (local if set, else global):

```text
feat(desktop): add vault info modal

List diagnostics were drifting from settings; Info now reads the same
shared builders as System Info.
```

## Message format

[Conventional Commits](https://www.conventionalcommits.org/), **no emoji** and **no special characters**:

```text
type(scope): short imperative summary

Optional body: why this change exists (1–2 sentences).
```

### Subject (first line)

The **subject is the entire first line**, including `type`, optional `(scope):`, and the summary. Count every character on that line.

| Rule | Detail |
|------|--------|
| Maximum | **120 characters** (hard cap). Prefer shorter when the meaning stays clear |
| Language | English |
| Mood | Imperative: “add”, “fix” — not “added”, “fixed” |
| Case | Lowercase after the colon |
| Period | **No** trailing period |
| Characters | ASCII letters, digits, and spaces. No emoji, no accented/decorative unicode. Punctuation only as the format needs it: `: ( ) - / !` |
| Overflow | Put extra detail in the **body**, do not wrap the subject onto a second line |

```text
feat(desktop): show remaining time on vault-root busy overlay
```

That whole line is the subject. `type(scope):` counts toward the 120.

### Body

No character maximum. Use it when the **why** is not obvious from the subject (typically 1–2 sentences). Not a file list.

Breaking change: `BREAKING CHANGE:` in the body, or `type(scope)!: summary` on the subject (still ≤ 120).

| Piece | Rule |
|-------|------|
| `type` | Required — see table below |
| `scope` | Optional; one primary area when it helps (`core`, `desktop`, …) |

Do not stack several unrelated changes in one commit when they can be split. Do not commit secrets, vault material, `.env`, or build artifacts (`target/`, `node_modules/`, `dist/`).

### Types

| Type | Use for |
|------|---------|
| `feat` | New capability |
| `fix` | Bug fix |
| `docs` | Documentation only |
| `style` | Formatting, no logic change |
| `refactor` | Restructure, same behavior |
| `perf` | Performance |
| `test` | Tests only |
| `chore` | Housekeeping, deps, lockfiles |
| `infra` | CI, packaging, toolchain |
| `revert` | Revert a previous commit |
| `release` | Version bump / changelog on a release branch |
| `hotfix` | Urgent production patch |

### Scopes

`core` · `rpc` · `daemon` · `ffi` · `desktop` · `electron` · `mobile` · `shared` · `docs` · `ci`

Omit the scope when the change is repo-wide or the type is enough (`docs: describe gitflow`).

### Examples

```text
feat(core): persist vault list from vault-root
fix(desktop): clear gate applying after resolve timeout
docs: add contributing guide and github templates
refactor(shared): share info-modal field builders
test(core): cover vault-root incomplete error path
chore: ignore local vscode workspace junk
infra(ci): run check on pull requests
release: v0.1.0
hotfix: unmount fuse before process exit
```

## How agents commit

Only when the human **asked** to commit. Then:

1. Confirm **effective** identity: `git config user.name` and `git config user.email`. If either is empty, **stop**.
2. In parallel: `git status`, `git diff`, `git log -5 --oneline` (match this repo’s style).
3. Stage only the intended files. Do not stage secrets or unrelated junk.
4. Commit with a HEREDOC message (no `-i`, no `--no-verify`, no `--author`, no trailers):

```bash
git commit -m "$(cat <<'EOF'
type(scope): summary

Why the change exists.

EOF
)"
```

5. **Always verify** the commit you just made:

```bash
git config user.name
git config user.email
git log -1 --format='author: %an <%ae>%ncommitter: %cn <%ce>%n%n%B'
```

Author and committer **must** match the effective name and email. The message **must not** mention an AI, model, or editor (`Co-authored-by:`, `Made-with:`, `Generated-by:`, Cursor, Claude, Copilot, ChatGPT, Grok, Composer, …).

If the message has AI credit and this is the commit you just created (not pushed): amend **only** to drop those lines. If name/email do not match the effective identity: **stop** and tell the human — do not rewrite author.

Never skip hooks. Never amend for any other reason unless the human asked and the usual amend safety checks pass.
