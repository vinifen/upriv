# Store crypto (Argon2id + XChaCha20-Poly1305)

## Stance

At rest the vault body is **`store/`** (Argon2id → HKDF → XChaCha20-Poly1305 chunks, AES-SIV names). **Backups** are frozen copies of that body. Portable files: ordinary **`.zip` of `store/`** (Recommended; zip is an envelope, no zip password) or **`.7z`** (Plan B). AES-256 in 7-Zip is not “broken”; we use Argon2id + AEAD for **offline password guessing**, not because XChaCha beats AES.

Never claim “more secure than 7-Zip” or “the same security as VeraCrypt.” Round-trip encrypt/decrypt is not a security proof. Closed-disk residual attack = guess the password paying Argon2id. In-app 5/60s throttle is not anti-offline.

## Do

- Primitives only via a mature library (no hand-rolled ChaCha/Poly1305/Argon2). Those crates are pinned in `dev/vendor/` (`[patch]`). Refresh is the checklist in `dev/vendor/MANIFEST.txt`; do not `cargo generate-lockfile`. Do not edit `vendor/*/src` except in a reviewed upgrade.
- Unique random salt; persist KDF params in `vault.header`. Cost is chosen **at vault create** (default **256 MiB / 3 passes**; also **128 MiB / 3**, **64 MiB / 3**, **32 MiB / 3** less-secure opt-in, **1 GiB / 1**, **2 GiB / 1**). UI: security of each preset + RAM needed to unlock — **not** phone vs desktop. Open uses the header everywhere. **Never** auto-pick or lower params because of the current device.
- Password unlocks master key once per open; each write = content key + new 192-bit CSPRNG nonce (not Argon2, not a RAM counter). See SECURITY-CRYPTO “Password, master key, edits, nonces”.
- Password change and unlock-RAM change (`vault_change_password`, `vault_change_kdf`) require that vault closed. Same master key, new salt, reseal the header wrap and the name index only. Write a backup zip of the current body first; if that zip fails, leave `store/` unchanged. Same password or same preset is rejected. A wrong password uses the same in-process unlock throttle as open.
- AEAD AAD is compact `serde_json` of a **struct in field order** (not pretty `vault.header`, not RFC 8785). One store format (`format_version` 1). Wrap and index bind version, **content identity** (not registry folder id), algos, and KDF params. Chunks bind version, content identity, file id, chunk index, chunk length, and a per-write version — not KDF salt/`m`/`t`/`p` and not `file_size`. Any other `format_version` is an unreadable store. Verify tags before any plaintext leaves `upriv-core`.
- `password_hint` in `config.toml` is **public** (list without unlock). UI must say so. Empty hint is safer than a hint that is the password.
- `store/` = live ciphertext. A backup is one **Stored** zip, no zip password: `README.md` and `config.toml` beside `store/` in `backups/<stamp>-<id>.zip` (pins: `backups/saves/<stamp>-<id>.zip`). `README.md` records the UTC time of that copy and the rounded size of the files in `store/` (not the exact length of the zip). That zip is the only backup form. Close streams that envelope straight into the zip; Close now writes none, and the next normal close does. Create-from-backup unpacks `store/` into a **new** vault, keeps the settings in that vault's own `config.toml`, and writes `DANGER-DO-NOT-EDIT-PERMANENT-DATA-LOSS.md` into the new `store/`. Export and backup write that same file before packing so the zip keeps it inside `store/`. The new vault does not keep `README.md`. Backup export copies one `.zip` into a chosen folder, or bundles several snapshot zips into one Stored zip; it never replaces a file already using the name. Export data folder zips the whole `.upriv` the same way (Stored, no zip password) while every vault is closed or in recovery: ciphertext as it is, never decrypted. Export of the live vault is the same envelope: user chooses a `.zip` of `store/` (**Recommended**), a `.7z` (warn: weaker offline guessing), or a plain-text `.zip` (**Insecure**, not encrypted at all, behind the vault password). The file is **`{display_name}.zip`** or **`{display_name}.7z`** (not registry id) in the folder the person chose, and never replaces a file already using that name: it takes the next free number (`{display_name} 2.zip`). Export requires **that** vault closed (other vaults may stay open). File zip/7z import and create-from-backup copy a frozen tree — they do not require the source vault closed. `.7z` never stores `.enc` blobs and does not carry the store-zip envelope. A `.7z` holds one outer folder named after the vault; a plain-text `.zip` holds the vault's files at its root. Both may carry `.upriv-config/` beside those files: `config.toml` and `workspace.json` (each behind its own export toggle, on by default) with a `README.md`. A new vault moves what that folder carries to its place and never keeps the folder. The zip envelope has **no** zip password. **Do not** present the zip as a custom “Upriv file” type — it is a normal `.zip` whose payload is Upriv ciphertext. A store zip is recognized by `store/header/vault.header`, not by a file merely named `vault.header` and not by a root `config.toml`. **Mobile:** same `store/` session via in-app file manager (no FUSE); never copy the vault to `filesDir` / OS temp to fake a mount.
- Recovery: dirty close or leftover `upriv_plain` workspace. Dead header/index → new vault from backup only. One chunk tag fail → that file, vault still opens.
- Greenfield. `dev/` is the first product, not a successor. One store format (`format_version` 1). One backup file: `backups/<stamp>-<id>.zip` (pins: `backups/saves/<stamp>-<id>.zip`). No reader, migrator, or second path for any other format or layout. New work is the current path only — do not keep a compatibility shim next to it.
- Lock = close, the only lock action. Close now is that close with no backup and, on `upriv_plain`, no closing pass and no overwrite; it still seals the index and drops the keys. A close already running can be told the same (`vault_close_hurry`), and the seal still finishes. Persistence on disk is `closed` only.
- Surface anti-brute-force: in **`upriv-core` session RAM** — serialize `open`; **5** failures / **60 s** → **60 s** block. Resets when the process exits. **No** JSON attempt counter. Does not stop offline guessing.
- Plaintext vault bytes on ordinary disk **only** for `upriv_plain` while open (the files sent to its folder, or every file with `plain_files = "whole"`), and as the plain-text `.zip` a person chose to export. Import/export/backup/password/recovery must not stage a decrypted tree (including “temp for 7zz”).

## Do not

- Weaken or auto-downgrade the KDF, or pick a preset from device type (phone/desktop).
- Use raw Argon2 output as every layer’s key (use HKDF domain separation).
- Pack `.enc` blobs into `.7z`; put a zip password on a store zip or a backup zip.
- Add a lock action other than close, or a storage mode besides `encrypted_dir` and `upriv_plain`.
- Claim in-app unlock backoff “prevents brute force,” or implement that backoff only in TypeScript.
- Implement crypto in TypeScript / Electron / Expo.
- Reorder AAD struct fields or “canonicalize” AAD JSON without a `format_version` bump.
- Put KDF salt/`m`/`t`/`p` or `file_size` back into chunk AAD. Password and unlock-RAM change keep the same master key and this chunk AAD; they reseal the header and the name index only.
